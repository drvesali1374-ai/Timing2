## ۲. تغییرات UI — هر دو نسخه (آنلاین/آفلاین)

### ۲.۱ فرم ویرایش عنصر کاری (`ParallelRelationsSection` / `RelationControls`)

- حذف کامل فیلتر `activityName === ownActivityName` — فیلتر مبنای نام فعالیت بود و با
  فعالیت‌های هم‌نام نادرست عمل می‌کرد؛ هویت اکنون صرفاً با `elementId` / `activityId` /
  `stationId` تعیین می‌شود (§۲ دستورالعمل).
- نامزدها: تمام عناصر پروژه (هر Activity/Station) منهای عنصر جاری و روابط فعال موجود.
- گروه‌بندی سلسله‌مراتبی **Station ← Activity ← Element** بر اساس شناسه‌های واقعی؛ نام
  Activity و Station کنار نام WorkElement نمایش داده می‌شود.
- برچسب «بین‌فعالیت» روی نامزدها/روابط سایر فعالیت‌ها + نشانهٔ فعالیت/ایستگاه عنصر مقابل
  در دیالوگ تأیید (§۲ قواعد ۶/۷/۸).
- روابط آرشیوشده قابل تشخیص (بخش جدا) و **Restore برای رابطهٔ بین‌فعالیت مجاز شد** —
  `RestoreRelationControl` دیگر دکمه را غیرفعال نمی‌کند؛ crossActivity فقط برچسب اطلاعاتی است (§۶).

### ۲.۲ جدول زمان‌سنجی دسکتاپ (`SheetGrid`)

## ۳. تغییرات API و سرویس

### ۳.۱ `src/application/overlap-service.ts`

- **`createRelation`**: حذف کامل شرط `elA.activityId !== elB.activityId` و خطای
  `CROSS_ACTIVITY_NOT_SUPPORTED` (422). دامنهٔ رابطه = یک Project. اعتبارسنجی‌های
  حفظ‌شده: وجود هر دو عنصر، تعلق به یک Project، منع خود-رابطه، منع تکراری، canonical.
- **`restoreRelation`**: حذف بلوک ممنوعیت بازگردانی بین‌فعالیت؛ در عوض دو اعتبارسنجی
  معنادار جایگزین شد: وجود هر دو عنصر (ELEMENT_NOT_FOUND در صورت حذف) و تعلق هر دو
  عنصر به Project رابطه (WRONG_PROJECT). Cross-Activity بودن به تنهایی هرگز مانع Restore نیست.
- `getElementRelations`: پرچم `crossActivity` حفظ شد اما فقط **اطلاعاتی** است (برچسب UI).
- ثابت `CROSS_ACTIVITY_ARCHIVE_REASON` حفظ شد — فقط برای شناسایی/نمایش روابط تاریخیِ
  آرشیوشده در v1.5.0؛ در سیاست جاری استفاده نمی‌شود.

### ۳.۲ محرک‌های حفظ‌شده (§۸ — بدون هیچ تضعیفی)

- `isObservedInCycle` / `hasComparableEvidence` / بازهٔ واقعی / Solver سراسری
  (`runFullValidation` + `assertNoDefiniteFailure`) کاملاً دست‌نخورده.
- `setCycleOverlaps` و `applyOverlapUpdatesInTx`: ثبت مقدار قطعی همچنان فقط وقتی مجاز
  است که **هر دو endpoint در همان CycleObservation** مشاهده و شواهد قابل‌مقایسه داشته باشند.
- UNREVIEWED از NO_OVERLAP جدا ماند؛ مقدار ساختگی/پیش‌فرض صفر ذخیره نمی‌شود.

## ۴. تغییرات DTO و ساختار داده

### ۴.۱ `SessionRelationDto` (برگهٔ زمان‌سنجی — §۷)

```
قبلی: { relationId, elementLowId, elementHighId, elementLowName, elementHighName, version }
جدید: + elementLowActivityId,  elementLowActivityName,  elementLowStationName,
       elementHighActivityId, elementHighActivityName, elementHighStationName
```

نام/فعالیت/ایستگاه **هر دو endpoint** از اطلاعات کامل پروژه حل می‌شود — نام عنصر خارج از
Activity جاری هرگز «؟» نمایش داده نمی‌شود. منبع داده batch است (یک کوئری
`workElement.findMany` برای کل پروژه + یک کوئری روابط) — بدون N+1.

### ۴.۲ `buildSessionDetail` — فیلتر روابط برگه

```
قبلی: AND: [ elementLowId IN elementIds, elementHighId IN elementIds ]   ← هر دو endpoint
جدید: OR:  [ elementLowId IN elementIds, elementHighId IN elementIds ]   ← حداقل یک endpoint
```

`buildGridRows` (Paste) همین تغییر را گرفت + حل نام عناصر خارجی از کل پروژه (batch).
مرتب‌سازی روابط با `orderBy: { createdAt: 'asc' }` پایدار شد.

### ۴.۳ مدل ردیف UI (`shared.ts` / `sheetGridRows` آفلاین)

`ParallelRowModel` جدید: `otherActivityName`, `otherStationName`, `crossActivity` — زیرردیف
بین‌فعالیت پس از روابط هم‌فعالیت (otherSort = 10000) مرتب می‌شود.

### ۴.۴ ماتریس آفلاین

`getOverlapMatrix` آفلاین فیلد `archiveReason` را در serialize روابط برمی‌گرداند (هم‌ارز
آنلاین — برای برچسب روابط آرشیوشدهٔ تاریخی).

## ۵. نحوه نمایش رابطه در دو Activity (§۷ دستورالعمل)

الگوی مفهومی پیاده‌سازی‌شده:

```
Activity 1 (برگهٔ اپراتور X):          Activity 2 (برگهٔ اپراتور Y):
  عنصر اصلی A                            عنصر اصلی B
  └─ زیرردیف رابطهٔ A-B [بین‌فعالیت]      └─ زیرردیف رابطهٔ B-A [بین‌فعالیت]
     (relationId واحد)                      (همان relationId واحد)
```

- هر دو محل از **یک رکورد ObservationOverlap** با همان `relationId` می‌خوانند؛ هیچ رکورد
  معکوس یا رابطهٔ جدید ساخته نمی‌شود.
- در هر برگه فقط زیرردیفِ endpoint حاضر در آن Activity ساخته می‌شود؛ عنصر خارجی هرگز
  WorkElement جدید یا ElementObservation ساختگی یا ستون برگه نیست.
- مقدار ویرایش‌شده از هر طرف، طرف مقابل را از همان منبع واحد به‌روز می‌کند.
- همهٔ اپراتورهای هر دو Activity درگیر، رابطه را در برگهٔ خود می‌بینند (استقلال مقدارهای
  چرخه‌ای هر اپراتور حفظ شد — §۶ ممیزی ج۲).

## ۶. رفتار روابط تاریخی

- روابطی که در v1.5.0 با دلیل `CROSS_ACTIVITY_NOT_SUPPORTED_BY_SESSION_SHEET` آرشیو شده
  بودند: **در فهرست روابط آرشیوشده قابل مشاهده‌اند و Restore آن‌ها مجاز است**؛ مقدارهای
  تاریخی `ObservationOverlap` آن‌ها حذف/بازنویسی نشده و با بازگردانی برمی‌گردد.
- به‌طور عمدی **خودکار فعال نمی‌شوند** — کاربر باید آگاهانه Restore کند (§۹).
- آرشیو دستی رابطهٔ بین‌فعالیت از هر دو سمت (برگهٔ هر دو Activity و فرم هر دو عنصر) مجاز
  است و مقدارهای تاریخی حفظ می‌شود.

## ۸. محدودیت‌های مقایسه‌پذیری چرخه‌ها (ثبت صریح — §۸ دستورالعمل)

مدل زمان‌سنجی: `StudySession = Activity × Operator × TimingMethod`؛ هر `CycleObservation`
متعلق به یک StudySession است و `ObservationOverlap = relationId + cycleId`.

1. **رابطهٔ بین‌فعالیت قابل ایجاد و نمایش است** — اما ثبت مقدار قطعی هم‌پوشانی فقط در
   چرخه‌ای معنا دارد که **هر دو عنصر در همان CycleObservation** مشاهده و شواهد
   قابل‌مقایسه (بازهٔ کامل یا مدت غیرتهی) داشته باشند. چون عنصر فعالیت دیگر معمولاً در
   چرخهٔ این جلسه مشاهده‌ای ندارد، سلول آن غیرفعال است و دلیل فارسی دقیق نمایش داده
   می‌شود («فلان عنصر در این چرخه مشاهده‌ای ندارد…»)؛ API نیز همین را با 422 اعمال می‌کند.
2. **محدودیت معماری ثبت‌شده:** برابر بودن شمارهٔ چرخهٔ دو Activity به معنی یکسان بودن
   چرخهٔ واقعی تولید نیست. مدل فعلی **سازوکار اتصال دو CycleObservation متعلق به دو
   Session** ندارد؛ بنابراین چرخهٔ ۱ از Activity اول **هرگز** خودکار معادل چرخهٔ ۱ از
   Activity دوم در نظر گرفته نمی‌شود و مقایسهٔ عددی بر مبنای cycleNo انجام نمی‌شود.
   ثبت و مقایسهٔ عددی هم‌پوشانی بین دو چرخهٔ مستقل نیازمند طراحی آتی «مدل چرخهٔ مشترک /
   اتصال دو CycleObservation» است که به‌صورت ضمنی و بدون ثبت رابطهٔ واقعی چرخه‌ها
   پیاده نشده و نباید شود.
3. اگر در آینده هر دو عنصر در یک چرخهٔ واحد واقعاً مشاهده شدند (سناریوی نظری)، منطق
   موجود مقایسه‌پذیری و Solver بدون تغییر عمل می‌کند.
