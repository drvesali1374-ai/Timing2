## ۳) علت ریشه‌ای هر باگ

1. **D&D:** در ادغام نهایی جلسه ۱، کامنت `var _treeSearch = {}; // جست‌وجوی درخت — §۷.۴` و تعریف `var _drag = null;` در یک خط ادغام شدند و تعریف دوم داخل کامنت افتاد. Strict Mode → `ReferenceError: _drag is not defined` روی هر dragstart.
2. **Race:** الف) `getScopeAllowances` مهاجرت self-heal را داخل `Promise.all` با دو کوئری خام موازی می‌کرد؛ کوئری‌ها می‌توانستند پیش از commit مهاجرت بخوانند. ب) مهاجرت‌های هم‌زمان چند تراکنش تعاملی رقیب روی SQLite می‌ساختند که در صف قفل نوشتن به timeout ۵ ثانیه‌ای می‌رسیدند؛ علاوه بر آن در حالت dev، تکرار ماژول در چند chunk باعث می‌شد نقشه درون‌فرایندی ماژول‌سطح مشترک نباشد.
3. **نوع والد:** مدل خروجی Resolver فقط عدد داشت چون در طراحی اولیه فرض شده بود نوع والد همیشه با نوع محلی یکسان است؛ Override با تغییر نوع (مجاز طبق §۲.۳) این فرض را شکست. UI هم برای سادگی از `row.valueType` استفاده می‌کرد.
4. **EXCLUDED:** چون ستون `value_type` در Prisma NOT NULL است و EXCLUDE مقدار ندارد، پیاده‌سازی اول `PERCENT` را به‌عنوان placeholder هاردکد کرد؛ Resolver همین مقدار ذخیره‌شده را بی‌بازبینی به UI می‌داد و نوع ساختگی تولید می‌کرد.

## ۴) راهکار پیاده‌سازی

1. **D&D آفلاین:** تعریف مستقل سه `var`؛ افزودن `data-sort-type/id/scope` به ردیف‌ها برای هدف‌یابی؛ درگ لمسی سازگار: `pointerdown` روی دستگیره → انتظار فشار طولانی ۳۰۰ms (حرکت > ۱۲px قبل از آن = لغو برای اسکرول) → Ghost شناور + `_drag` + جلوگیری از اسکرول با `touchmove` غیرpassive → هدف با `document.elementsFromPoint` و هایلایت `drop-target` مشابه دسکتاپ → `pointerup` روی هدف = همان `onReorder` دسکتاپ. دسکتاپ/کیبورد دست‌نخورده (فقط pointerType لمسی/قلم). دستگیره درگ به ردیف‌های عنصرِ درخت اضافه شد (رفع مغایرت با راهنمای §۷.۵).
2. **Race:** الف) `getScopeAllowances` ابتدا `loadProjectAllowanceContext` (مهاجرت) را کامل می‌کند، سپس دو خواندن مستقل را موازی می‌زند. ب) مهاجرت با نقشه `globalThis` per پروژه سریال شد (همه نمونه‌های ماژول یک وعده مشترک می‌گیرند) + تراکنش با `timeout: 15s` و در صورت خطا، بازبینی مارکر (اگر مهاجرت رقیب کامل شده → ادامه بدون خطا) و یک تلاش مجدد.
3. **نوع والد:** Resolver «والد مستقیم scope» را برمی‌گرداند (تصمیم محلی → نزدیک‌ترین تصمیم بالاتر؛ ردیف ارثی → خودِ منبع) با `parentValue/parentValueType/parentApplicationBasis/parentScopeType/parentDecisionExists/parentMode`. UI والد را فقط با نوع و مبنای خودش فرمت می‌کند و منبع (خط/ایستگاه/…) را هم نشان می‌دهد.
4. **EXCLUDED:** حالت حذف از ارث‌بری مستقل از نوع مقدار فعال شد: نوع نمایشی از ۱) نزدیک‌ترین تصمیم **فعال** بالادست، ۲) وگرنه پیش‌فرض تعریف مرکزی، ۳) وگرنه null (خنثی «—») مشتق می‌شود — هم در ذخیره (`computeExcludeValueType`) و هم در Resolver (بازتولید برای داده قدیمی). منوی Restore چهارحالته: «حذف تخصیص محلی» / «بازگردانی به مقدار والد» / «بازگردانی الونس والد» / «حذف استثنای محلی». Restore همچنان فقط تصمیم محلی را حذف می‌کند.
5. **هم‌ارزی:** تمام تغییرات عیناً در `formulas.js`/`db.js`/`views-allowances.js` آینه شد؛ آزمون §P/§D همان ورودی را به هر دو موتور می‌دهد و خروجی JSON را مقایسه می‌کند.
